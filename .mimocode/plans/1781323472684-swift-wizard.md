# Service Worker 生命周期修复：初始化阶段状态丢失

## 问题

初始化阶段（模型下载 + 索引构建）关闭弹窗后，Service Worker 休眠/被终止。再次打开弹窗时：
1. 初始化状态丢失（isIndexing、进度、阶段全部在内存中）
2. 进度条不显示
3. 用户无法感知当前状态

## 根因

1. **SW 空闲被杀**：关闭弹窗后无活跃 Port，模型下载期间 SW 无实际工作，Chrome 判定空闲并终止
2. **进度状态无持久化**：`isIndexing`、`indexingProgress`、`indexingPhase` 仅存内存，SW 重启后全部丢失
3. **重启后重新开始**：SW 重启执行 `defineBackground`，`createContainer()` 创建新实例（`isIndexing=false`），检查 `hasPersistedData()` 后重新执行 `buildIndex()`
4. **连接时序问题**：SW 重启后可能还未设置 `isIndexing=true`，popup 连接时拿到的是"未索引"状态

## 修复方案

### 1. 添加 alarms 权限，SW 保活

**文件**: `wxt.config.ts`

```ts
permissions: ['bookmarks', 'activeTab', 'storage', 'favicon', 'history', 'tabs', 'alarms'],
```

### 2. 新增 SW 保活模块

**新文件**: `core/keepalive.ts`

- 索引期间每 25 秒触发一次 alarm，防止 SW 被杀
- `startKeepalive()` / `stopKeepalive()` 控制开关
- alarm 回调中自我续期，形成保活链

### 3. 索引进度持久化到 chrome.storage.session

**文件**: `core/bookmark-indexer.ts`

在 `buildIndex()` 过程中，将进度写入 `chrome.storage.session`：

```ts
// 开始时
await chrome.storage.session.set({ indexingState: { isIndexing: true, phase: 'loading_model', current: 0, total: 0 } });

// 进度更新时（每批次）
await chrome.storage.session.set({ indexingState: { isIndexing: true, phase: 'indexing', current, total } });

// 完成时
await chrome.storage.session.remove('indexingState');
```

### 4. SW 重启时恢复索引状态

**文件**: `entrypoints/background.ts`

`defineBackground` 启动时，先检查 `chrome.storage.session` 中是否有未完成的索引状态：

```ts
const sessionState = await chrome.storage.session.get('indexingState');
if (sessionState.indexingState?.isIndexing) {
  // 上次索引未完成，重新开始
  console.log('[Background] 检测到未完成的索引，重新构建');
}
```

### 5. getIndexStatus 优先读取持久化状态

**文件**: `core/bookmark-indexer.ts`

`getIndexStatus()` 方法增加：先查内存状态，再查 `chrome.storage.session`：

```ts
async getIndexStatus() {
  if (this.isIndexing) return /* 内存状态 */;
  
  // 检查 session storage 中是否有未完成的索引
  const session = await chrome.storage.session.get('indexingState');
  if (session.indexingState?.isIndexing) {
    return { isIndexing: true, phase: session.indexingState.phase, ... };
  }
  
  // 正常完成状态
  return { isIndexing: false, ... };
}
```

### 6. Popup 连接时立即查询状态

**文件**: `entrypoints/popup/hooks/useIndexStatus.ts`

连接 Port 后，除了监听推送，还主动发一次 `get-index-status` 消息获取当前状态：

```ts
useEffect(() => {
  const port = chrome.runtime.connect({ name: "popup" });
  port.onMessage.addListener((msg) => {
    if (msg.type === "index-status") setIndexStatus(msg.payload);
  });
  // 主动查询一次当前状态
  chrome.runtime.sendMessage({ type: "get-index-status" }).then((status) => {
    if (status) setIndexStatus(status);
  });
  return () => port.disconnect();
}, []);
```

### 7. message-handler 增加 get-index-status 处理

**文件**: `core/message-handler.ts`

```ts
case 'get-index-status': {
  return await bookmarkIndexer.getIndexStatus();
}
```

## 修改文件清单

| 文件 | 改动 |
|------|------|
| `wxt.config.ts` | 添加 `alarms` 权限 |
| `core/keepalive.ts` | **新建** - SW 保活模块 |
| `core/bookmark-indexer.ts` | `buildIndex` 中写入 session storage 进度；`getIndexStatus` 读取 session storage |
| `entrypoints/background.ts` | 启动时调用 keepalive；检查未完成索引状态 |
| `core/message-handler.ts` | 添加 `get-index-status` 消息处理 |
| `entrypoints/popup/hooks/useIndexStatus.ts` | 连接时主动查询状态 |

## 验证方式

1. `pnpm build` 构建通过
2. 加载扩展，触发索引构建
3. 构建期间关闭弹窗，等待 30 秒以上
4. 重新打开弹窗，验证进度条正确显示
5. 等待索引完成后关闭再打开，验证正常状态
6. 验证搜索功能正常
